# Restocker

The Restocker keeps your stock honest across marketplaces. Two
scenarios it handles:

1. **Multi-quantity Vinted seller.** You have 3 of a t-shirt. Set it
   to **2 restocks**: as each of the first two sells, the restocker
   reposts a fresh listing for the next unit so the item stays
   continuously listed without you doing anything. The third sale
   closes it out.
2. **Cross-platform linked items.** Same item listed on both Depop
   and Vinted. When it sells on Depop, the restocker takes the
   Vinted copy down so you don&rsquo;t oversell. (And vice versa.)

## Where it lives

The **Restocker** tab in the panel. Each tracked item is one row.

## Adding an item

From the **Listings** tab, find the row, set **Restock = on**, and
enter the number of **restocks**: how many times you want SaleLinx to
put the item back up after it sells.

That is one fewer than the number of units you have, and it is worth
getting the right way round:

- **0 restocks** is the default, and it is the ordinary
  one-of-a-kind case. The item stays tracked, Depop advertises it as
  1, and the first sale closes it out and takes the linked partner
  down. It is never reposted.
- **2 restocks** means 3 units: two reposts, then the item closes out.

The Restock toggle and the number live inline on each Listings row, so
you can set up multiple items without leaving the dashboard.

## How it works (Vinted multi-quantity)

When you have N units tracked:

1. The marketplace listing sells. Vinted marks it sold.
2. The restocker checks (next scan tick) and confirms the item is
   closed using a live API check, not just a cached state.
3. It reposts a fresh copy of the same listing - same title,
   description, photos, price, mapped fields.
4. The remaining count decrements by 1 in your SaleLinx record.
5. The last sale closes the item out instead of reposting it, so you
   never end up with a live listing and no stock behind it. Restock
   then auto-disables for that item.

Reposts use the cloud-stored copy of the listing (title,
description, photos, mapped fields) so nothing is lost even if the
marketplace removes the old listing.

## How it works (cross-platform)

When you have an item linked across Depop and Vinted (typically
because you crosslisted it):

1. The item sells on one marketplace.
2. The restocker takes the other side down so you can&rsquo;t
   accidentally sell the same physical unit twice.
3. If you have restocks left, it then reposts the listing on
   whichever side is configured. If that sale was the last unit,
   both sides stay down.

[Linking](/docs/automate/linking) is what powers the &ldquo;these
are the same physical item&rdquo; relationship. Successful
crosslists set links automatically; you can also pair pre-existing
inventory manually in the Linking tab.

## Schedule

The restocker runs as part of the panel&rsquo;s background bot loop
while the panel is open. It uses safe pacing between checks and
reposts so the marketplaces don&rsquo;t flag the burst as automated
activity.

## What it won&rsquo;t do

- **Won&rsquo;t restock without a confirmed sale.** SaleLinx waits
  for a clean sold signal before acting, so transient marketplace
  glitches don&rsquo;t trigger phantom reposts.
- **Won&rsquo;t loop on stale state.** If something marks a listing
  as sold incorrectly, the next check spots the live signal and
  self-corrects without reposting.
- **Doesn&rsquo;t modify photos.** If you want each repost to look
  fresh (different photo crop, different first image), use
  [Relist](/docs/inventory/relist) instead - it&rsquo;s designed
  for that.

## Plan and access

Restocker is **Business only**. Pro doesn&rsquo;t include it.

Restocker also requires [Cloud sync](/docs/inventory/cloud-sync)
(for the reposted content) and, for cross-platform pairs,
[Linking](/docs/automate/linking).
